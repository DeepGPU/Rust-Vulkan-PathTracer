[VAi] Vulkan기반 온디바이스 Ai 프레임워크 소개

Q: 왜 새로운 온디바이스 AI 프레임워크가 필요합니까?

현재 온디바이스 GPU를 타깃으로 하는 AI 서비스 개발 파이프라인에는 여전히 많은 어려움이 존재합니다. 특히 온디바이스 환경에서 AI 추론 서비스를 배포하기 위해 많은 기업들이 TensorFlow Lite나 ONNX Runtime에 의존하고 있지만, 성능에 민감한 특성상 이들 프레임워크만으로는 충분하지 않아 직접 네이티브 개발을 선택하는 사례도 적지 않습니다.

우리가 제공하는 VAi(Vulkan-based Ai) 프레임워크는 이러한 문제를 해결하기 위해 설계되었습니다. 데스크톱 테스트부터 실제 온디바이스 실행까지 이어지는 통합 개발 프로세스를 제공하며, 개발자가 요구에 맞게 유연하게 커스터마이징할 수 있는 구조를 갖추고 있습니다. 이는 성능에 극도로 민감한 온디바이스 AI 개발 환경에서 중요한 경쟁력이 될 것입니다.

VAi의 주요 강점:
1. 모든 GPU에 동일한 백앤드 API 제공 
 - 예시: (ONNX Runtime) NVIDIA→CUDA / AMD→ROCm(HIP) / Intel→Level Zero / Apple→Metal(CoreML) / Android→NNAPI,  (VAi) 모든 GPU→Vulkan
 - GPU별 백엔드가 다르면 일관된 성능 유지와 코드 품질 관리가 어렵습니다. 실제로 PyTorch도 CUDA 이외의 GPU에서는 성능 저하나 버그가 자주 보고됩니다.

2. Vulkan의 저수준 GPU 제어 기능을 활용한 고급 최적화
 - 기존 GPU API(CUDA등)로는 불가능한 수준의 메모리 효율화와 연산 속도 개선이 가능하며, 드라이버 수준 제어를 통해 병목을 최소화합니다.

3. C++ 기반의 경량 프레임워크
 - 기존 AI 프레임워크는 주로 Python을 기반으로 빠른 프로토타이핑에는 유리하지만,
실제 온디바이스 배포 시에는 성능과 메모리 측면의 큰 제약이 있습니다.
 - VAI는 순수 C++로 동작하므로 이러한 비효율이 전혀 없으며, 최대의 런타임 성능을 제공합니다.

Q: 어떤 개발자와 기업이 VAi를 통해 가장 큰 가치를 얻을 수 있습니까?

[개인 개발자]
1. 온디바이스 GPU 환경에서 AI 추론 성능을 극한까지 끌어올리고자 하는 개발자
– 모바일, 임베디드, XR 기기 등 제한된 하드웨어에서 고성능 AI를 구현하려는 기술 중심형 개발자층

2. AI 엔진을 완전히 네이티브 C++로 다루고자 하는 고급 개발자
– Python 기반 프레임워크의 성능 제약과 오버헤드에 한계를 느끼는 엔지니어, 시스템 프로그래머, 렌더링·그래픽스 엔진 개발자 등

[기업]
3. GPU 제조사 (AMD, Intel, Qualcomm, Samsung, Huawei 등)
– 엔비디아가 장악한 AI GPU 생태계에서 점유율을 확보하려는 제조사들에게 VAi는 매우 전략적인 의미를 갖습니다.
Vulkan 기반 단일 백엔드를 통해 CUDA 종속 장벽을 낮추어 개발자들이 자연스럽게 비(非)엔비디아 GPU로 확장할 수 있는 길을 열어주기 때문입니다.

4. 게임 엔진 및 그래픽스 엔진 개발사 (Epic Games, Unity, 펄어비스, 크래프톤 등)
– Vulkan은 본래 게임 친화적 API로, 렌더링 엔진과의 통합이 용이합니다.
VAI를 엔진 내부에 탑재하면 그래픽 파이프라인과 AI 연산을 동일 GPU에서 병렬 처리할 수 있어, 실시간 콘텐츠 생성이나 NPC 행동 AI 등에 즉시 적용이 가능합니다.

5. 온디바이스 AI 솔루션을 필요로 하는 산업군
– 자율주행, 모바일, XR/AR, IoT 기기 등 네트워크 의존 없이 실시간 추론이 필요한 제품군에서 VAI의 활용 가능성이 높습니다.

Q: VAi 프로젝트를 시작하게 된 계기는 무엇입니까?

저는 오랜 기간 C++을 이용해 GPGPU 기반 비전 처리, 과학 연산, 그래픽스 개발을 해왔습니다.
동시에 Python과 PyTorch를 활용한 AI 모델 연구·개발도 오래전부터 병행해왔지만,
두 환경은 구조적으로 너무 달라 실제 하이브리드로 개발할 때 성능 손실과 비효율적인 워크플로우를 피하기 어려웠습니다.

AI 프레임워크 대부분이 Python 중심으로 설계되어 있어,
C++ 개발자가 GPU 성능을 최대한 활용하기 위해서는 별도의 인터페이스 계층과 복잡한 컨텍스트 스위칭을 감수해야 했습니다.
이 과정에서 “GPU와 직접 맞닿은 C++ 기반의 순수 네이티브 AI 프레임워크”의 필요성을 절실히 느꼈습니다.

그 결과, 수년 전부터 이를 구상해왔고, 약 8개월 전 본격적으로 팀을 구성하여
VAi(Vulkan-based Ai) 프로젝트를 시작하게 되었습니다.
이 프로젝트는 단순히 새로운 프레임워크를 만드는 것이 아니라,
AI 개발을 진정한 로우레벨 GPU 프로그래밍의 영역으로 확장하려는 시도이기도 합니다.

Q: VAi는 무엇을 목표로 하는 기술입니까?

VAi(Vulkan-based AI)는 다양한 GPU 하드웨어가 존재하는 환경에서도,
AI 모델을 동일한 방식으로 실행·최적화·배포할 수 있도록 설계된
온디바이스 AI에 특화된 엔진입니다.
개발자는 하드웨어 차이를 의식하지 않고,
데스크톱에서 작성한 코드를 모바일·임베디드 환경에 그대로 적용할 수 있으며,
프레임워크 전체가 C++로 구성되어 파이썬 계층 없이
순수 네이티브 성능을 확보할 수 있습니다.

Q: 기존 프레임워크와 비교했을 때 VAi의 차별점은 무엇입니까?

1. 단일 GPU 백엔드(Vulkan) 기반
기존 프레임워크는 GPU 제조사마다 서로 다른 백엔드를 요구하여 성능 편차와 유지보수 비용이 발생합니다.
VAi는 Vulkan 하나로 모든 GPU를 지원하여 일관된 개발 환경을 제공합니다.

2. C++ 네이티브 런타임
파이썬 중심 워크플로우의 오버헤드 없이, C++에서 GPU 메모리·파이프라인을 직접 제어해 제한된 온디바이스 환경에서도 최대 성능을 확보할 수 있습니다.

3. Vulkan 저수준 제어 기반의 고급 최적화
CUDA의 단일 스트림 기반 순차 실행과 달리, Vulkan은 동기화를 명시하지 않는 한 단일 큐에서도 의존성이 없는 커맨드가 자동 병렬 실행될 수 있습니다.
또한 스페셜라이제이션 상수, 스파스 리소스 등을 활용해 효율적 메모리·대역폭 사용이 가능합니다.

4. 엔진 레벨 커스터마이징
TensorFlow Lite, ONNX Runtime은 내부 구조가 폐쇄적·복잡해 런타임 로직을 수정하는건 불가능하고 커스텀 gpu 커널 작성 또한 어렵거나 불가능 합니다.
VAi는 처음부터 커스터마이징을 염두하고 설계되어, 커널코드 수정 및 샛성은 물론 메모리 정책·연산 구조까지 직접 확장할 수 있습니다.

5. 데스크톱→온디바이스 동일 파이프라인
별도의 모델 변환 없이 동일 코드로 데스크톱에서 테스트하고 모바일·임베디드에 배포할 수 있어 개발 및 유지보수 비용이 크게 감소합니다.

Q: VAi가 제공하는 핵심 가치는 무엇입니까?

1. 벤더 종속성 제거
GPU 제조사별로 상이한 API를 관리할 필요 없이, 단일 Vulkan 백엔드로 개발과 배포가 가능합니다.

2. 고성능 온디바이스 추론
전력·대역폭이 제한된 모바일 환경에서도 안정적인 고성능을 제공할 수 있습니다.

3. 완전한 오픈소스·확장성
엔진 내부 아키텍처까지 분석·개조 가능하며, 필요한 기능을 자유롭게 추가할 수 있습니다.

4. 일관된 개발 경험
데스크톱 테스트, 임베디드 배포, 성능 최적화를 모두 동일한 파이프라인에서 처리할 수 있습니다.
